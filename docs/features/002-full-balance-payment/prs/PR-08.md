# PR-08: End-to-end payment journeys, deploy smoke and cross-path checks

## Goal
Prove the slice end to end: Playwright journeys J-1..J-3 in a browser (pay, edge cases, pending + automatic check,
control placement and privacy, accessibility, admin record), the deploy smoke that pays once on `demo` marked as smoke,
and four integration checks that need both API PRs (both sides agree after every step, no full numbers anywhere,
one log event per state change, origin marker). Test-only PR (reviewer `pr-light`).

## Design context (excerpts)
**E2E rules (design §15.1, §15.4):** each local journey starts with `api.reset()`; arrange purchases with
`api.simulatePurchase(cardId, amount)`; steer with `api.setBankOutcome(...)` / the panel; drive through
`CardholderPage` → `ReviewPage` → `ReceiptPage`; end with `expectNoSeriousViolations(page)` (`src/a11y.ts`). Only T-E-3
waits the real 10 s budget (assert ≤ 12 s). Role/label locators only. Accessible names fixed by PR-03: buttons "Pay full
balance", "Confirm payment of £…", "Check status", "Review again", "Set"; regions "Balance", "Linked current account",
"Recent card activity", "Current account recent activity", "Fake bank (simulation control)"; selects "Next debit
outcome", "Next status check"; card list link "Cardholder view for {card name}". Admin (PR-07): heading "Balance owed
£…", Activity table caption "Transaction history", Payments section, record page sections "What the cardholder saw",
"Acceptance", "Payment", "Events". If a name differs in the built UI, STOP and report (do not edit pages).
**Deploy smoke (DEC-14, DEC-15):** `smoke/pay.spec.ts` runs only in the `smoke` project against `DEMO_URL`, never
resets; uses `test.use({ extraHTTPHeaders: { 'X-CardLab-Origin': 'deploy-smoke' } })` in the spec file
(PLANNER-DECISION: no config change; the header is harmless on other calls and only the quote endpoint reads it);
simulate a £1.00 purchase on Ops van, set the fake bank to Complete explicitly, pay the full balance, assert W-2 and that
the receipt appears within 3 s of pressing confirm (AC-26), and the admin record shows "origin: smoke" and a simulated
outcome. End state (balance £0.00) is a valid demo state.
**Integration cross-path checks:** T-I-8 reads both sides after every step (cardholder view + `GET /api/fake-bank`);
T-I-13 extends 001's `NoPanTests` (scan every response body, captured log record and `Database.DumpAllRowsAsync()` with
`PanScanner.AssertNoFullNumbers`; actor kind cardholder, never "Sam Ellis"); T-I-14 reads `factory.Logs` for
`PaymentStateChanged` (EventId 1003: paymentId, cardId, lastFour, kind, amount, fromState, toState, reason, durationMs)
and `BankCallUnanswered` (1005); T-I-18 checks the origin header end to end (quote, receipt, record, list, activity).
**PanScanner (design §10):** the second pattern is the literal seeded account number "51907731" (`seed.linkedAccount.accountNumber`).
