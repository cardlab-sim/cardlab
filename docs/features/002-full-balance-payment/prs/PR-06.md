# PR-06: Cardholder and fake-bank API with payment-flow integration tests

## Goal
Implement the handler bodies of `CardholderEndpoints` (view, quote, confirm, check, receipt) and `FakeBankEndpoints`
(read and steer), mapping `PaymentService` / `CardholderViewService` results to the §7 wire shapes and ProblemDetails,
and prove the whole payment flow through HTTP on SQL Server: completion on both sides, refusals, exactly-once,
concurrency, timeouts, status checks, limits unaffected and the view's latency budget.

## Design context (excerpts)
**Routes (PR-00, complete) and responses (design §7).** JSON camelCase; amounts two-decimal strings; times ISO-8601.
| Method & path | Response |
|---|---|
| `GET /api/cardholder/cards/{id}` | `200 CardholderViewDto` (`PaymentDtoMapper.ToDto(view)`); `404` |
| `POST /api/cardholder/cards/{id}/quotes` (optional header `X-CardLab-Origin`) | `201 QuoteDto` (Location optional); `409 {code: nothing_to_pay\|above_limit\|payment_pending, message, balanceOwed, pendingReference?}`; `404` |
| `POST .../payments/{reference}/confirm` | `200 ReceiptDto` (`repeated`); `409 {code: balance_changed\|quote_refused, message (W-6), balanceOwed}`; `409 {code: payment_pending, message (W-9), pendingReference, amount, balanceOwed}`; `404` unknown, malformed or another card's reference |
| `POST .../payments/{reference}/check` | `200 ReceiptDto` (W-10 when unanswered); `404` |
| `GET .../payments/{reference}` | `200 ReceiptDto`; `404` |
| `GET /api/fake-bank` | `200 FakeBankDto {nextDebitOutcome, nextStatusCheck, account {lastFour, availableBalance}, entries}` (unset steering reads `complete` / `answers`; entries = last 10) |
| `PUT /api/fake-bank/steering` | body `SteeringRequest`; merge: absent fields keep their value (PLANNER-DECISION); `200 FakeBankDto`; unknown value → `400` ValidationProblem, nothing stored |

Errors are ProblemDetails (`TypedResults.Problem(statusCode, title, extensions: { code, message, balanceOwed, … })`);
404 title "Card not found" / "Payment not found". Route `{reference}` is parsed with `PaymentReference.TryParse` (bad →
404, design §9). Origin: `PaymentWireNames.OriginFromHeader(request.Headers["X-CardLab-Origin"])` (exact `deploy-smoke` →
DeploySmoke). Steering wire values: next debit `complete | refuse_insufficient_funds | refuse_account_unavailable |
timeout_debit_applied | timeout_not_received` ↔ `NextDebitOutcome`; status `answers | does_not_answer` ↔ `NextStatusCheck`
(map privately in `FakeBankEndpoints`). The bank account is `IOptions<SeedOptions>.Value.LinkedAccount.BankAccountRef`.
Lock timeouts and SQL failures already map to 503 via `CardLabExceptionHandler` (001).
**DEC-13:** the GET view is pure; the SPA calls `check`. **DEC-5:** concurrent confirms join the in-flight task (PR-04).
