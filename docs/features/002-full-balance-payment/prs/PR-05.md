# PR-05: SQL payment store, persisted fake bank, migration, seed and reset

## Goal
Make payments and the fake current account real on SQL Server: the additive migration `AddPayments` (payment and
fake-bank tables), `SqlCardStore`'s five payment reads, `SqlPaymentWriter` inside the card lock, the persisted
`SqlFakeBank` with its one-shot steering (ADR-007), `SystemPaymentReferences`, the idempotent seed of the linked account
and bank account, and the extended test reset. Proven by the two contract suites from PR-02 (unchanged) plus
adapter-specific integration tests. No HTTP changes (PR-06/PR-07).

## Design context (excerpts)
**Migration `AddPayments` (design §6; additive, forward-only).** Amounts `decimal(12,2)`; enums as short strings (enum
names, like 001); times `datetime2(3)` UTC.

| Table | Columns | Keys / indexes / rules |
|---|---|---|
| `LinkedAccount` | `Id`, `AccountId` FK BusinessAccount, `DisplayName nvarchar(200)`, `LastFour char(4)`, `BankAccountRef uniqueidentifier`, `AuthorityBasis nvarchar(400)` | PK; unique `AccountId` (one per business, R-2). The full account number is never stored (NFR-3): the seed derives `LastFour` and discards the rest |
| `PaymentQuote` | `Reference varchar(12)` PK, `CardId` FK, `LinkedAccountId` FK, `Kind varchar(10)`, `Amount`, `Fee`, `Total`, `FromLabel nvarchar(200)`, `ToLabel nvarchar(200)`, `WordingVersion varchar(10)`, `Heading nvarchar(100)`, `RenderedLines nvarchar(2000)` (W-1 lines joined with `\n`), `ButtonLabel nvarchar(100)`, `ActorKind varchar(12)`, `ActorId`, `ActorName nvarchar(200)`, `AuthorityBasis nvarchar(400)`, `Origin varchar(20)` (cardholder_view/deploy_smoke, DEC-15), `CreatedAtUtc`, `Status varchar(10)` (Open/Confirmed/Refused), `RefusedAtUtc null`, `RefusalReason varchar(30) null`, `BalanceAtRefusal decimal null` | PK Reference; index `(CardId, CreatedAtUtc DESC)`. Only `Status`, `RefusedAtUtc`, `RefusalReason`, `BalanceAtRefusal` ever change (R-14 "shown-and-accepted part never changed") |
| `Payment` | `Id` PK, `Reference` FK unique → PaymentQuote, `CardId` FK, `Kind`, `Amount`, `Fee`, `State varchar(10)`, `CreatedAtUtc` (acceptance time), `SettledAtUtc null`, `EffectiveAtUtc null`, `BankDebitedAtUtc null`, `FailureReason varchar(30) null`, `BalanceBefore decimal null`, `BalanceAfter decimal null`, `Simulated bit` | PK; unique `Reference` (R-7: at most one payment per reference); **filtered unique index `UX_Payment_OnePending (CardId) WHERE State = 'Pending'`** (R-8 enforced by the database as well as the rules); index `(CardId, CreatedAtUtc DESC)`; `IX_Payment_Completed (CardId, State) INCLUDE (Amount)` for the balance sum |
| `PaymentEvent` | `Id` PK, `Reference` FK, `PaymentId null`, `AtUtc`, `Kind varchar(30)`, `FromState varchar(10) null`, `ToState varchar(10) null`, `Detail nvarchar(400) null`, `Simulated bit` | append-only; index `(Reference, AtUtc)` |
| `BankAccount` (fake bank) | `Id` PK (= `BankAccountRef`), `LastFour char(4)`, `AvailableBalance decimal(12,2)` | one row seeded (£25,000.00) |
| `BankDebitRequest` (fake bank) | `Reference varchar(12)` PK, `AccountId` FK BankAccount, `Amount`, `Outcome varchar(30)` (Completed/RefusedInsufficientFunds/RefusedAccountUnavailable), `ReceivedAtUtc`, `DebitedAtUtc null`, `Simulated bit` | the bank's memory of every request it received; a repeated request with a known reference returns this row (idempotent) |
| `BankEntry` (fake bank) | `Id` PK, `AccountId` FK, `Reference varchar(12)` unique, `Amount`, `Narrative nvarchar(200)`, `PostedAtUtc` | the ledger; index `(AccountId, PostedAtUtc DESC)` |
| `BankSteering` (fake bank) | `Id int` PK (= 1), `NextDebitOutcome varchar(30) null`, `NextStatusCheck varchar(20) null` | one row; read-and-clear inside the bank's own transaction |

Balance owed (R-1) = `SUM(Transaction.Amount WHERE Outcome='Approved')` − `SUM(Payment.Amount WHERE State='Completed')`,
floored at £0.00 (floor with `Money -`). Category spend (001) still sums only `Transaction` rows. **No query joins `Bank*`
tables with card or payment tables (DEC-2, reviewer rule)**; the bank never writes card/payment tables and the store
never writes `Bank*` tables. No update/delete paths for quote shown columns, settled payments, events, bank entries or
debit requests.

**Fake bank debit (flow 6, DEC-6).** Own transaction with `sp_getapplock` on `bank:{accountId}` (5 s); known reference →
return the recorded outcome (Completed with its `DebitedAtUtc`, or Refused); else read-and-clear `BankSteering.NextDebitOutcome`
(Simulated = a value was set, including an explicit Complete); refuse InsufficientFunds when steered or when Amount >
AvailableBalance (insert a `BankDebitRequest` with the refusal so a status check can answer Refused); Complete /
TimeoutDebitApplied → insert `BankDebitRequest` + `BankEntry`, decrement the balance, commit; TimeoutNotReceived →
commit only the steering clear, nothing else; both timeout modes then `await Task.Delay(Timeout.Infinite, ct)`.
**Status (DEC-7):** read-and-clear `NextStatusCheck`; DoesNotAnswer → `await Task.Delay(Timeout.Infinite, ct)`;
otherwise from `BankDebitRequest`: Completed(DebitedAtUtc) / Refused(reason) / NotReceived when no row. Steering never
changes balance, ledger or records.

**Seed (design §6, idempotent, in `Seeder.EnsureSeedAsync`).** From `SeedOptions.LinkedAccount` (PR-00): `LinkedAccount`
for the seeded business (DisplayName, `LastFour` = last 4 of `AccountNumber`, BankAccountRef, AuthorityBasis); `BankAccount`
with Id = BankAccountRef, same last four, `AvailableBalance` = `OpeningBalance`, created only when missing (never reset on
restart, AC-22); `BankSteering` row Id 1 with nulls when missing. Seed values: "Brightline Supplies Ltd current account",
account number "51907731" (only "7731" reaches the database), ref `5a3e1d2c-7b4f-4c1a-9e2d-000000000731`, £25,000.00.

**Test reset (DEC-16, `TestDataReset.ResetAsync`, one transaction):** additionally delete `PaymentEvent`, `Payment`,
`PaymentQuote`, `BankEntry`, `BankDebitRequest`; set `BankSteering` fields to null; set the seeded `BankAccount` back to
the opening balance; keep `LinkedAccount`. Mapped only when `CardLab:TestEndpoints=true` (001; unchanged route).

**SystemPaymentReferences (DEC-8):** 5 random bytes from `RandomNumberGenerator` → 40 bits → 8 Crockford base32 chars
(`0123456789ABCDEFGHJKMNPQRSTVWXYZ`) → `PAY-XXXXXXXX`.

**EF details:** new row classes go in `Model/PaymentEntities.cs` (quote, payment, event, linked account) and
`FakeBank/BankEntities.cs` (bank rows); map them in `CardLabDbContext.OnModelCreating` with the exact names, types and
indexes above (filtered index via `.HasFilter("[State] = 'Pending'")`). Generate the migration with
`dotnet tool run dotnet-ef migrations add AddPayments --project src/CardLab.Infrastructure --startup-project src/CardLab.Api`,
(set `ASPNETCORE_ENVIRONMENT=Development` if design time needs the development connection string),
then rename the two generated files to `20261107000000_AddPayments.cs` / `.Designer.cs` (and the `[Migration("…")]` id
to `20261107000000_AddPayments`) so the scope check passes; the snapshot must match the model.

## Harness to use

account + cards + `LinkedAccount` row per `CreateStoreAsync` (see 001 `SqlCardStoreContractTests` for the pattern) and a
