# PR-04: Payment application services: quote, three-step confirm, status check, view

## Goal
Implement `PaymentService` (quote, confirm, check status, receipt), `CardholderViewService` (the aggregate read) and the
`InFlightPayments` registry in `src/CardLab.Domain/Application` (tier-3 path). This is where exactly-once, one-in-flight
and "both sides agree" are orchestrated (DEC-3, DEC-5, ADR-006): lock #1 validates and creates the pending payment, the
bank is called outside the lock with a time budget, lock #2 settles. Unit-tested with the in-memory store and the
scriptable `FakeBank`; HTTP is PR-06.

## Design context (excerpts)
**DEC-3 three-step confirm (ADR-006).** Step 1 (in `WithCardLockAsync`): `GetQuoteAsync(ref)` (null → ReferenceNotFound;
also when the quote's `Card` is another card); `GetPendingPaymentAsync`; sums → `BalanceRules.Owed`;
`ConfirmRules.Decide(quote, status, paymentForQuote?.State, otherPending, owed)`:
- `Create` → `CreatePayment(NewPayment(ref, Full, amount, fee, now))`, `AppendEvent(ConfirmCreated, none→Pending)`,
  `SetQuoteStatus(Confirmed)`, commit; log `PaymentStateChanged(none→pending)` and `PaymentConfirmAttempt(created)`.
- `Repeat` → `AppendEvent(ConfirmRepeated)`, commit; then await the in-flight task if any (DEC-5), else return the stored
  receipt; `Repeated = true`; log `PaymentConfirmAttempt(repeated)`.
- `RefuseBalanceChanged(newOwed)` → `SetQuoteStatus(Refused, "balance_changed", newOwed, now)`, `AppendEvent(ConfirmRefused,
  Detail "balance_changed")`, commit, no bank call → `PaymentError.BalanceChanged(W-6(newOwed), newOwed)`.
- `RefuseAlreadyRefused(owed)` → `AppendEvent(ConfirmRefused)` → `QuoteRefused(W-6(owed), owed)`.
- `RefusePendingExists(ref, amount)` → `AppendEvent(ConfirmRefused, Detail "payment_pending")` → `PaymentPending(W-9, …)`.
Step 2 (no lock): `AppendEvent(DebitRequested)` belongs in step 1's unit of work (PLANNER-DECISION: recorded before the
call, so a crash still shows the request was about to be sent); `RequestDebitAsync(new DebitRequest(account.BankRef, ref,
amount, "CardLab card payment " + ref), budget)` where `budget` = `new CancellationTokenSource(BankTimeoutSeconds)`, NOT linked to `ct` (BUG-002: a client disconnect
never cancels the debit; steps 2-3 run to completion). `OperationCanceledException` from the budget, or any other
adapter exception → treated as `BankOutcome.Unknown` (Detail = exception type name; design §9).
Step 3 (lock, `CancellationToken.None`): `PaymentStateMachine.Apply(Pending, outcome)`; Completed → sums give
`BalanceBefore` (owed before applying) and `BalanceAfter` (= before − amount, floored); Failed → before = after;
`SettlePayment(id, Settlement(state, reason, settledAt = now, effectiveAt = DebitedAtUtc ?? now, debitedAt, before,
after, outcome.Simulated))`; `AppendEvent(BankCompleted | BankRefused)`; Unknown → `AppendEvent(BankUnanswered)` only,
stay Pending, log `BankCallUnanswered(ref, "debit")`. Lock timeout in step 3 (`CardLockTimeoutException`) → one retry after `SettleLockRetryMs`; if that also
times out the payment stays Pending (the next check settles it, the bank is idempotent) and the receipt is W-5.
PLANNER-DECISION (design §9 says "stays Pending with event `Detail = "settle_lock_timeout"`" but not how to write it
without the lock): make one further best-effort `WithCardLockAsync` that only appends `BankUnanswered` with
`Detail = "settle_lock_timeout"`; if that throws too, swallow it (no event) and still return W-5.
**DEC-5 in-flight join:** register the in-flight task for the reference before step 1 commits (so a second confirm that
sees `Repeat` always finds it); remove when done. `InFlightPayments.GetOrAdd(ref, start)` returns the same task to
concurrent callers; `TryGet` finds it. Single host (ADR-001).
**Status check (flow 2):** read the quote/payment (inside a short lock or via the store); not Pending → return the stored
receipt (no bank call, no event); else `GetDebitStatusAsync(budget)` outside the lock, then lock: Completed → settle
with `EffectiveAt = DebitedAtUtc ?? now`, event StatusCheckCompleted; Refused → Failed(reason), StatusCheckRefused;
NotReceived → Failed(NotReceived), StatusCheckNotReceived (message = W-4 text); Unknown → StatusCheckUnanswered, stay
Pending, message W-10, log `BankCallUnanswered(ref, "status")`. Never re-sends the debit.
**Quote:** inside the lock: owed, pending → `BalanceRules.Availability`; not Available → error with W-7 / W-8 / W-9
(W-9 names the pending payment's amount and reference), nothing stored; else `QuoteRules.Create(_references.Next(),
card ref, card name, account, owed, PaymentActor(Cardholder, cardId.Value, cardholderName), origin, now)` + `AppendQuote`.
Card name / cardholder from `ICardStore.GetCardAsync`; account from `GetLinkedAccountAsync`.
**Receipt:** `Receipt(ref, state, amount, fee, Time = EffectiveAt when settled else CreatedAt, FromLabel, ToLabel, reason,
Message = WordingV1.Receipt(state, reason, amount, currentOwed, ref) (W-10 instead after an unanswered check), BalanceOwed =
current owed, Repeated, Origin)`.
**CardholderView:** card, balance (`GetBalanceAsync`), pending payment (from `ListPaymentRecordsAsync`), availability +
message, pending receipt (W-5), account + `GetAccountAsync` available balance, `ListActivityAsync(id, 10)`,
`ListRecentEntriesAsync(bankRef, 10)`. Pure read: never calls `GetDebitStatusAsync` (DEC-13).
**Logs (design §12):** `CardLabEvents.PaymentStateChanged` once per state change incl. none → pending (never for
Unknown); `PaymentConfirmAttempt` per confirm (`created|repeated|refused_balance_changed|refused_already_refused|refused_payment_pending`);
`BankCallUnanswered` (`debit|status`). Field values: wire names, `Money.ToString()`, last four only. No `AuditEvent`
rows for payments (DEC-1).
