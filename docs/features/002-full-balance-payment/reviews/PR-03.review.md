# PR-03 review: Cardholder web journey (view, review, receipt, fake-bank panel, API clients)

## Verdict: CHANGES

2 blockers, 4 major, 4 minor, nits at the end. No blocker needs a reviewer `recheck`. Each fix comes with a check
the orchestrator can run. Re-run `pr` only if the coder departs from the fix spec in B2.

Overall the PR is in good shape. The pages follow the stub contracts and DEC-10: every W-* string reaches the UI
verbatim from the API or the fake, and the SPA builds no customer wording. The confirm double-submit guard works,
the review screen holds only W-1 plus the confirm button, the fake-bank panel comes last and never appears on the
review or receipt pages, and the tests mostly use hand-written literals through `renderWithApi`. The blockers are two
contract breaks with downstream PRs (PR-08's locators and PR-07's fake). The majors are places where the fake or the
page behaves differently from the design.
