The fix is right and sits in one place. `BuildReceipt` now takes `payment.Settlement?.BalanceAfter ?? pendingBalance`
(`PaymentService.cs:296`), and that value feeds both `Message` and `BalanceOwed`. So every rebuild of a settled payment
returns the original receipt, and a Pending one shows the current owed (design §5 erratum BUG-012, R-7, AC-9, AC-12, AC-13,
AC-36). The one finding: `StoredReceiptAsync` passes a `Money.Zero` placeholder for settled payments. Nothing reads it today,
but it hides mutation M1 from test 1 and would show a plausible "£0.00" if `BuildReceipt` ever stopped preferring the
settlement.
