# PR-09: Admin API: card endpoints, health, test reset, security headers

## Goal
Expose the admin surface over HTTP: list/read cards, freeze/unfreeze, set/remove limits, transaction and audit lists
(R-4, R-6, R-8), plus `GET /api/health` (R-14), the flag-guarded `POST /api/test/reset` (DEC-16), the security-header
middleware the ZAP baseline needs, and the 503 mapping for lock timeouts and database failures.

## Acceptance criteria covered (verbatim from requirements)
| AC | Covers | Given | When | Then |
|----|--------|-------|------|------|
| AC-1 | R-1, R-6 | an active card | the admin freezes it | the card's status is frozen and one audit event exists: action freeze, actor = the seeded admin, UTC time, card last four, old status active, new status frozen |
| AC-2 | R-1, R-6 | a frozen card | the admin freezes it again | the status stays frozen and no new audit event is created |

## Design context (excerpts)
**Endpoints (§7, DEC-19)** — thin handlers: parse route/body → `CardControlsService` or `ICardStore` → DTO / status.

| Method & path | Response |
|---|---|
| `GET /api/cards` | `200 [{id, name, cardholderName, lastFour, status}]` |
| `GET /api/cards/{id}` | `200 {id, name, cardholderName, lastFour, status, limits:[{category, period, amount}]}`; `404` |
| `POST /api/cards/{id}/freeze` | `200 {status:"frozen"}` (also for a no-op); `404` |
| `POST /api/cards/{id}/unfreeze` | `200 {status:"active"}`; `404` |
| `PUT /api/cards/{id}/limits/{category}/{period}` body `{amount}` | `200 {category, period, amount}`; `400` ProblemDetails (amount outside R-11, unknown category/period); `404` |
| `DELETE /api/cards/{id}/limits/{category}/{period}` | `204` (also no-op, no audit); `404` card unknown |
| `GET /api/cards/{id}/transactions` | `200 [{id, occurredAt, amount, category, merchant, outcome, reason}]` newest first; `404` |
| `GET /api/cards/{id}/audit` | `200 [{id, atUtc, actorName, action, oldValue, newValue}]` newest first; `404` |
| `GET /api/health` | `200 {commit, database:"ok"}` / `503 {commit, database:"unreachable"}` |
| `POST /api/test/reset` | `204`; route mapped only when `CardLab:TestEndpoints=true` (Program.cs does that) |

Wire names via `WireNames` (categories snake_case, `day|week|month`, `active|frozen`, audit actions `limit_changed` ...);
amounts via `Money.ToString()`. Errors: unknown card → `TypedResults.Problem(statusCode: 404, title: "Card not found")`;
invalid amount text (`WireNames.TryParseAmount` fails or null) or `DomainError.InvalidAmount` → `TypedResults.ValidationProblem(
{ ["amount"] = [...] })`; unknown category/period → `ValidationProblem({ ["category"|"period"] = [...] })`. Nothing is stored
on any 400 (AC-9). Transactions/audit for an unknown id → 404 (check `GetCardAsync` first).

**Health (§12):** `DatabaseProbe.CanConnectAsync` runs `SELECT 1` with a 5 s command timeout and returns false on
`SqlException`/`InvalidOperationException`/timeout; commit from `CardLabOptions.Commit`, falling back to
`Assembly.GetEntryAssembly()?.GetCustomAttribute<AssemblyInformationalVersionAttribute>()?.InformationalVersion`.
**Test reset (DEC-16):** in one transaction delete all `Transaction`, `AuditEvent` and `SpendLimit` rows (bulk
`ExecuteDeleteAsync` is fine here; this is a test-only path) and set every card's `Status` to `Active`.

**Security headers (§10):** see the doc comment in `SecurityHeaders.cs` (nosniff, Referrer-Policy no-referrer,
X-Frame-Options DENY, Permissions-Policy, COOP/CORP same-origin, CSP self-only without inline scripts, `Cache-Control:
no-store` on `/api/*`), applied with `app.Use(...)` + `Response.OnStarting` so every response (including static files and
errors) carries them. HSTS comes from `UseHsts` outside Development (Program.cs).

**Error mapping (§9):** `CardLabExceptionHandler.TryHandleAsync`: `CardLockTimeoutException` → 503 ProblemDetails "Try
again"; `SqlException` or a `DbUpdateException`/`InvalidOperationException` wrapping one (connection failure) → 503 "Service
unavailable"; write with `IProblemDetailsService` (inject via constructor) and return true; anything else → false. Never
include the exception message (it might carry request data).

## Harness to use
Harness note (amend 2026-11-05, PR-05 review): `Result<_, DomainError>.Error` defaults to `CardNotFound` on success, so always assert `IsOk` (true or false) before asserting `Error`.
`[Collection("sql")]` + `IClassFixture<ApiFactory>` (or `ApiFactoryWithoutTestEndpoints`), `factory.CreateApiClient()`
(typed, returns status + body + raw), `factory.Database` for arrange/counts (`CountAuditEventsAsync`,
`SeedTransactionsAsync`), `PanScanner.AssertNoPan(raw, "...")` from TestKit. `ErrorMappingTests` builds the handler with a
`ServiceCollection` that has `AddProblemDetails()` and a `DefaultHttpContext` whose `RequestServices` is that provider.
