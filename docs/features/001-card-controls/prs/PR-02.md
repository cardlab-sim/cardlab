# PR-02: Web foundation: tokens, primitives, formatters, API clients, card list

## Goal

shell, money/time/label formatters, the fetch `HttpApiClient`, the in-memory `FakeApiClient`, the `renderWithApi` test

## Design context (excerpts)
**Tokens (§4.1, DEC-13, DEC-17)** in `web/src/styles/tokens.css` as CSS custom properties; components never use raw hex:
primary `#0F172A` / on-primary `#FFFFFF`, secondary `#1E3A8A`, accent `#A16207` / on-accent `#FFFFFF`, background
`#F8FAFC`, foreground `#020617`, card `#FFFFFF`, muted `#E8ECF1`, muted-foreground `#475569`, border `#E2E8F0`,
destructive `#DC2626` / on-destructive `#FFFFFF`, ring `#0F172A`; status: active `#166534` on `#DCFCE7`, frozen
`#1E3A8A` on `#DBEAFE`, approved `#166534`, declined `#991B1B` on `#FEE2E2`. Type: Inter (`@fontsource/inter`, already
imported in `main.tsx`), base 16 px, line-height 1.5, scale 14/16/20/24/32, `font-variant-numeric: tabular-nums` on
amounts. Spacing 4/8/12/16/24/32/48 px; radius 4 px; focus ring 2 px solid `var(--color-ring)` with 2 px offset.
Style: Minimalism & Swiss: white space, 1 px borders, no shadows, one accent, 150-250 ms transitions.

**Checkable UI rules (§4.1)** — text contrast ≥ 4.5:1, non-text ≥ 3:1; every action keyboard-operable with a visible
focus ring (never removed); every input has a visible `<label>`, errors inline under the field with `aria-describedby`
and `role="alert"`; status shown as text in a badge, never colour alone; submit feedback = pending state then a notice;
amounts `£1,234.56`, times Europe/London `25 Oct 2026 00:30`; tables inside an `overflow-x: auto` container, no page
scroll at 1024-1440 px; `prefers-reduced-motion` disables transitions; buttons ≥ 44 px tall and ≥ 8 px apart; no icons;
semantic HTML (`<button>`, `<table>`, `<form>`, `<nav>`), no div click handlers; no modals; no toasts.

**Layout:** app shell with a header (CardLab, "Brightline Supplies Ltd", "Sam Ellis"), content max-width 1200 px.
Card list `/`: heading "Cards" and one table (Name, Cardholder, Last four, Status badge, "Open" link).

**ApiClient semantics** (`web/src/api/apiClient.ts`, complete): paths of design §7 —
`GET /api/cards`, `GET /api/cards/{id}`, `POST /api/cards/{id}/freeze|unfreeze`, `PUT|DELETE
/api/cards/{id}/limits/{category}/{period}` (PUT body `{amount}`), `GET /api/cards/{id}/transactions|audit`,
`POST /api/cards/{id}/simulate-purchase` (body `{amount, category, merchant, timestamp?}`). Admin errors are
ProblemDetails (`application/problem+json`, `errors` for validation). `simulatePurchase` gets the decision body with 200
(approved / card_frozen / limit_exceeded), 400 (invalid_request + `problems`) and 404 (card_not_found).

**FakeApiClient** behaviour is specified in its doc comment (`fakeApiClient.ts`); amount validation mirrors R-11: a limit
amount must match `^\d+(\.\d{1,2})?$` and be ≤ 1000000.00, else reject with `ApiError(400, {errors: {amount: [...]}})`.

**Formatters:** `formatMoney` works on the string (split integer/fraction, group with commas, pad to 2 decimals) — never
`Number()` arithmetic. `formatLondonTime` uses `Intl.DateTimeFormat('en-GB', {timeZone: 'Europe/London', day: 'numeric',
month: 'short', year: 'numeric', hour: '2-digit', minute: '2-digit', hourCycle: 'h23'})` and assembles
`"{day} {Mon} {year} {HH}:{mm}"` from `formatToParts` (en-GB short month for September is "Sept"; map it to "Sep").
