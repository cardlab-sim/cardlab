# PR-03: Azure infrastructure and deploy workflow (OIDC, Bicep, smoke)

## Goal
Make a green `main` deploy itself to the free Azure `demo` environment: Bicep for App Service F1 (Linux) + Azure SQL
free offer, a `deploy.yml` that publishes the self-contained host with the SPA, logs in with OIDC, applies the Bicep,
zip-deploys, waits for `/api/health` to report the new commit and runs the Playwright `smoke` project; plus the
human's one-off setup guide. Independent of the application code, so it runs in wave 1; it first runs for real on the
final merge to `main`.

## Acceptance criteria covered (verbatim from requirements)

| AC-27 | R-10 | a merge to main with green CI | the deploy workflow runs | the Azure environment serves the new build, identifiable by commit on its health endpoint |

AC-27..AC-29 are validator evidence (T-C-2..T-C-4); AC-34's endpoint is PR-09, this PR adds the deploy-time health wait. The smoke spec itself (AC-36) is PR-10.

## Design context (excerpts)
**DEC-3:** one App Service plan F1 (Linux) hosting API + SPA; self-contained `linux-x64` publish (the .NET 10 runtime may
not be offered on F1); no Always On; 60 CPU-min/day quota; warm-up ≤ 60 s.
**DEC-10:** `infra/main.bicep` + `infra/demo.bicepparam`: App Service plan F1 Linux (`sku {name: 'F1', tier: 'Free'}`,
`kind: 'linux'`, `reserved: true`); web app (system-assigned identity, `httpsOnly: true`, `minTlsVersion: '1.2'`,
`ftpsState: 'Disabled'`, `alwaysOn: false`, start command for the self-contained binary, e.g. `appCommandLine:
'./CardLab.Api'`); Azure SQL logical server with Entra-only authentication (`administrators.azureADOnlyAuthentication:
true`, the human's identity as admin, `minimalTlsVersion: '1.2'`); database on the free offer (`useFreeLimit: true`,
`freeLimitExhaustionBehavior: 'AutoPause'`, serverless GP_S_Gen5); firewall rule allowing Azure services
(`0.0.0.0`-`0.0.0.0`). Deployed idempotently by `deploy.yml` via `az deployment group create`.
**DEC-11:** the web app connects with its managed identity: `Server=tcp:<server>.database.windows.net;Database=cardlab;
Authentication=Active Directory Default;Encrypt=True` (no password anywhere). Human one-off T-SQL as the SQL Entra admin:
`CREATE USER [$AZURE_WEBAPP_NAME] FROM EXTERNAL PROVIDER; ALTER ROLE db_ddladmin ADD MEMBER [$AZURE_WEBAPP_NAME];
ALTER ROLE db_datareader ADD MEMBER [$AZURE_WEBAPP_NAME]; ALTER ROLE db_datawriter ADD MEMBER [$AZURE_WEBAPP_NAME];` (the web app's name) (ddladmin because migrations run at startup).
**Config (§11):** `CardLab:LookupKey` on `demo` is a random 32-byte base64 value set once by the human as App Service
setting `CardLab__LookupKey`; it must never be in GitHub, and redeploys must preserve it. `CardLab:TestEndpoints` is
never set on demo. `CardLab:Commit` is set by the deploy workflow (`CardLab__Commit=$GITHUB_SHA`) and the publish stamps
`-p:SourceRevisionId=$GITHUB_SHA`. Repo variables (identifiers, not secrets): `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`,
`AZURE_SUBSCRIPTION_ID`, `AZURE_RESOURCE_GROUP`, `AZURE_WEBAPP_NAME`, `DEMO_URL`, `TICKET_KEY_PATTERN`.
**Deploy (§14):** on `push` to `main` and `workflow_dispatch`, environment `demo`, `permissions: id-token: write,
contents: read`: `npm ci --prefix web && npm run build --prefix web`; `dotnet publish src/CardLab.Api -c Release -r
linux-x64 --self-contained true -p:SourceRevisionId=$GITHUB_SHA -o publish` (the csproj copies `web/dist` into
`wwwroot`); `azure/login@v2` (OIDC: client-id/tenant-id/subscription-id from vars); `az deployment group create -g
$AZURE_RESOURCE_GROUP -f infra/main.bicep -p infra/demo.bicepparam`; `azure/webapps-deploy@v3` with the `publish`
folder; poll `GET $DEMO_URL/api/health` every 10 s for up to 5 min until `commit == $GITHUB_SHA` and `database == "ok"`
(fail the run otherwise); then `npm ci --prefix tests/e2e`, `npx --prefix tests/e2e playwright install --with-deps
chromium`, `DEMO_URL=... npm run e2e --prefix tests/e2e -- --project smoke`. Rollback = re-run `workflow_dispatch` on
the previous green commit (schema forward-only).
**Security (§10):** OIDC federated credential scoped to `repo:<owner>/cardlab:ref:refs/heads/main` and
`repo:<owner>/cardlab:environment:demo`; `Contributor` on the resource group only; no stored cloud credentials.
**DEC-21 (document only):** the human enables branch protection on `main` requiring `ci / backend`, `ci / web`,
`ci / e2e`, `ci / ticket-key` and CodeQL; GitHub secret scanning stays enabled.

## Planner decisions (PLANNER-DECISION)
- **Preserving `CardLab__LookupKey`:** keep `appSettings` out of the Bicep site resource and set the non-secret settings
  (`ConnectionStrings__CardLab`, `CardLab__Commit`, `ASPNETCORE_ENVIRONMENT=Production`) with `az webapp config
  appsettings set` in `deploy.yml` after the Bicep step (merge semantics). Document in `azure-setup.md` how to confirm
  after the second deploy that the lookup key survived. (Design: "Bicep declares the setting name only, existing value
  preserved".)
- **SQL Entra admin identity:** two extra repo variables, `AZURE_SQL_ADMIN_LOGIN` and `AZURE_SQL_ADMIN_OBJECT_ID`
  (identifiers, not secrets), read by `demo.bicepparam` via `readEnvironmentVariable(...)`; plus `AZURE_SQL_SERVER_NAME`.
  The design lists the human as admin but no variable for it.
