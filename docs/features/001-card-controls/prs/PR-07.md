# PR-07: Card detail page: status, limits, audit, simulate, transactions

## Goal
Build `/cards/:id`, the admin's working page: freeze/unfreeze, the limits table and form, the audit list, the
simulate-purchase form with its result, and the transaction history, following every §4.1 rule. Tested with the
`FakeApiClient`; the real API arrives in wave 3 and the browser journeys in PR-10.

## Design context (excerpts)
**Layout (§4.1).** Heading with the card name, `•••• 0001` and a status badge (text "Active"/"Frozen") plus the
Freeze/Unfreeze button; two columns at ≥ 1024 px, stacked below: left "Spend limits" (table + inline add/edit form:
category select, period select, amount input, Save; Remove per row) and "Audit" (list, newest first); right "Simulate
purchase" (amount, category, merchant; result notice with outcome and reason) and "Transactions" (table, newest first).
No modals; every action is a form or button with inline feedback. Use `CardDetailPage.module.css` for layout (CSS grid,
breakpoint 1024 px, tokens only).

**Rules (§4.1, checkable):** visible `<label>` on every input; errors inline under the field with `aria-describedby` and
`role="alert"` (use `TextField`/`SelectField`); status as text badge, never colour alone; button pending state then a
notice (use `Button pending` + `Notice`); amounts via `formatMoney`, times via `formatLondonTime`; tables via `DataTable`
(overflow container); semantic HTML; no div click handlers; no icons.

**Behaviour.** Load `getCard`, `listTransactions`, `listAudit` on mount; after any successful action refetch all three.
Freeze/Unfreeze: one button whose label follows the status. Limits form: Save calls `setLimit(category, period, amount)`
(saving an existing pair replaces it); a 400 `ApiError` shows `problem.errors.amount[0]` (or a generic message) inline
under Amount; empty or non-numeric amount is rejected client-side with the same inline error. Remove buttons have
accessible names like "Remove Fuel day limit". Simulate: `simulatePurchase(id, {amount, category, merchant})` (no
timestamp: the server uses now); show a Notice with the outcome badge, the reason code text (e.g. `limit_exceeded`, as
AC-22 asks for the reason code) and each limit's remaining; `problems` render inline per field; then refetch. Audit
items: action label, actor name, London time, `old → new` values. Unknown card (`ApiError` 404 from `getCard`) →
Notice "Card not found" with a link to `/`. Other load errors → error Notice.
