## Design context (excerpts)
**Money (design §5, R-11; high-risk).** `readonly record struct Money` in namespace `CardLab.Domain` (folder `Money/`;
the namespace is the root so the type name is not shadowed). Construction only via `TryFromDecimal(decimal, out Money)`:
fails for more than 2 decimal places (`decimal.Round(v, 2) != v`) and for negative values (PLANNER-DECISION: Money is
never negative; subtraction floors at zero). Store the value normalised to scale 2 so `50.0` and `50.00` are equal with
equal hash codes. `+` exact; `-` floors at `Zero` (via `Max`); `<, >, <=, >=`, `CompareTo` by amount;
`ToString()` = `Amount.ToString("0.00", CultureInfo.InvariantCulture)` (e.g. `"1234.56"`, the wire format).
**MoneyBounds:** `IsValidTransactionAmount` £0.01..£1,000,000.00 inclusive; `IsValidLimitAmount` £0.00..£1,000,000.00
inclusive (£0.00 blocks the category).

**WireNames (design §7).** Exact lower-case names; parsing is exact (no trimming, no case folding):
categories `travel, fuel, meals_and_entertainment, software_and_subscriptions, office_supplies, advertising,
professional_services, other`; periods `day, week, month`; status `active, frozen`; outcomes `approved, declined`;
reasons `approved, card_frozen, limit_exceeded, card_not_found, invalid_request`; audit actions `freeze, unfreeze,
limit_set, limit_changed, limit_removed`. `TryParseAmount`: `decimal.TryParse(text, NumberStyles.AllowLeadingSign |
NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, out v)` and nothing else (no exponent, no thousands, no
whitespace); bounds and dp are checked elsewhere.

**LookupHash.** 32 bytes as 64 lower-case hex chars (`Convert.ToHexStringLower`), `FromBytes` throws `ArgumentException`
unless exactly 32 bytes; `ToBytes` = `Convert.FromHexString(Hex)`.

**ICardStore contract (design §5, DEC-4)** — see the doc comments in `src/CardLab.Domain/Ports/ICardStore.cs`; summary:
`WithCardLockAsync` runs the work under an exclusive per-card lock; writes become visible only when the work returns and
are discarded when it throws; `GetStateAsync` is null for an unknown id; `SumApprovedSpendAsync` sums approved rows of a
category with `StartUtc <= OccurredAt < EndUtcExclusive` compared as instants; `UpsertLimit` never creates a second row
for one (category, period); lists are newest first; `AppendTransaction` returns the store-assigned id.

**InMemoryCardStore (§15.2).** Per-card `SemaphoreSlim(1,1)`; the writer works on a copy of the card's state and the
store applies the copy when the work returns. Ids are deterministic (e.g. a counter turned into a `Guid`), never
`Guid.NewGuid()` (unit tests must not use randomness). `DateTimeOffset` comparison operators already compare instants.

**Contract suite rule:** the SQL adapter (PR-06) runs these tests against one database per class that also contains the
three seeded cards, so every contract test must assert only on the cards it seeded itself (filter by id; check relative
order, not list equality).

**CapturingLogger.** Record `EventId.Name` as `EventName`, the formatted message, and the structured fields from
`TState` when it is `IReadOnlyList<KeyValuePair<string, object?>>` (drop `{OriginalFormat}`). `IsEnabled` → true;
`BeginScope` → a no-op disposable. Thread-safe (lock).

**FakeCardNumberLookup:** `SHA256.HashData(Encoding.ASCII.GetBytes(digits))` → `LookupHash.FromBytes`; count calls with
`Interlocked.Increment`. **FakeClock:** stores UTC (`ToUniversalTime()`). **PanScanner:** regex `[0-9]{16,}` (not `\d`,
which matches non-ASCII digits); `AssertNoPan` throws `Xunit.Sdk.XunitException` naming `where` and showing only the last
four of each hit.

**Builders:** defaults as documented in `Builders.cs`; `CardBuilder` numbers `99990002` + 8-digit counter, last four from
the number, lookup via `FakeCardNumberLookup.Instance`; `CardBuilder.From(Seed.OpsVan)` reuses the seed values;
`TestMoney.Of` uses `decimal.Parse(..., CultureInfo.InvariantCulture)` + `Money.TryFromDecimal` and throws
`ArgumentException` otherwise.

## Planner decisions (PLANNER-DECISION)
- `Money` rejects negative values (design says only "rejects > 2 dp"); AC-9's -£1.00 is still rejected, just earlier.
- `WireNames` moved into this PR (it was not assigned in the design) because PR-04 and PR-05 both need it in wave 2.
- `LookupHash` is a hex-string value object so it has value equality (design: `binary(32)` in SQL).
- Store-assigned ids (`AppendTransaction` returns `TransactionId`) and `GetStateAsync` returning `CardState?` are
  skeleton interface refinements of design §5 (see `ICardStore.cs`).
