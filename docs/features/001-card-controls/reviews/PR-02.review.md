## Judgements on the coder's notes
- **setup.ts cleanup**: confirmed. Fix it in a skeleton delta PR-00b before PR-07 (F6); the fallback is a one-liner in PR-07's brief.
- **Caption "Card list"**: accepted. The brief and design name only the heading "Cards" and no caption. The DataTable contract requires a visible caption, so a distinct name avoids two identical visible titles. Record it in PR-10's brief (F7).
- **`aria-label="Open {name}"`**: accepted. The accessible name begins with the visible text "Open", which satisfies WCAG 2.5.3 (label in name) and voice control, and it matches T-W-7's "Open Ops van".
- **Extra cases**: accepted, and justified in the PR body. Each one asserts behaviour, not names. Of note, `"999999999999999.99"` in T-W-1 is the only case that catches `Number()` rounding, which is the design's stated rule. The select-field wiring, the app shell identity and skip link, the loading text and the base-url prefix each guard a §4.1 rule or a skeleton parameter.
- **Public repo / non-CardLab references**: none. I checked the diff and both commit messages for private names, local paths, emails, external URLs and foreign product names. Fixture cardholders (Dana Fox, Lee Park) are fictional, `http://localhost:5000` appears only in a test, and the commit author and `Co-Authored-By` trailer are the repo owner's standard attribution.
