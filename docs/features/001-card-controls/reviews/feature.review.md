## Verdict: **CHANGES**

0 blockers, 2 major (1 `upstream:design`), 11 minor (3 `upstream:design`, 1 for the human), nits.

The product code is consistent with the requirements and the design. The money, limit and period logic in `src/CardLab.Domain` is correct against R-5, R-11, R-12, R-13 and AC-10..AC-18 and AC-30..AC-33. The per-card `sp_getapplock` lock wraps every card write, and the 10-way burst through the API proves it (T-I-6). NFR-1 holds on every path I traced (see *NFR-1 path audit*). CI on the integrated head is green.

Why the verdict is not READY: two findings will very likely fail validation if they are left in.
- **F-1:** on `demo`, the serverless database pauses after 60 idle minutes. Startup migration has no retry, so the first visit after an idle hour crash-loops the host, which puts NFR-5's 60 s warm-up (AC-34, AC-36) at risk.
- **F-2:** the keyboard-only evidence for AC-37 skips J-3 (simulate purchase).

Both fixes are small, and the orchestrator can verify every fix below with the stated check. **No `recheck` by me is needed.** F-1 is `upstream:design`. Route it to the human, or decide it under the standing instruction and record it as a design erratum like BUG-001/004/005.
