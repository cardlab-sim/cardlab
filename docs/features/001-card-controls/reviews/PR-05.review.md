## Design check
- Interfaces match §5 and the digest: `CardControls` is pure, and `null` means no-op. `SetLimit` is always a change. The value format `"{Category}/{Period}/{Money}"` uses enum names and `Money.ToString()` (invariant, 2 dp). Status values are `nameof(CardStatus.X)`.
- §8 flow followed. Amount validation comes before the lock, so the store is never touched on `InvalidAmount` (AC-9). The lock wraps read, rule and writes, and the log is written after commit. Unknown card is reported as `Fail(CardNotFound)` with nothing written, for all four operations (code correct; test gap BL-1).
- DEC-12/§12 log fields: `ActorId`, `ActorName`, `CardId`, `LastFour`, `Action` (wire name). There is one event per real change and none for no-ops.
- No speculative generality. `ChangeStatusAsync` is a justified shared helper for the two status operations. There are no new packages and no edits outside owned files.
