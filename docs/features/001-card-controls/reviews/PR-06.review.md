# PR-06 review: SQL store, schema, seed and integration harness

## Verdict: APPROVE WITH FIXES

No blockers. 2 major, 5 minor, nits. The schema matches design §6 column for column (types, fixed lengths, precision,
`IX_Transaction_Spend ... INCLUDE (Amount)`, both DESC history indexes, no PAN column). The lock follows DEC-4 exactly
(`card:{id}`, Exclusive, Transaction owner, 5000 ms, parameterised, `@r < 0` means timeout). HMAC follows DEC-8, and the seeder
follows DEC-9 plus the brief's AdminId planner decision. Spend is half-open by instant. The two majors are failure-path
defects in `WithCardLockAsync` / `SqlCardWriter.SetStatus` that no current test reaches. I reproduced both against LocalDB.

## Coder notes: judgement
- **Gate instead of a 7 s sleep in T-I-17:** accepted. It is stronger and deterministic: the lock is held for exactly as long as the assertions need. The global-lock and ignored-result mutations both kill it.
- **`CreateStoreAsync` renaming duplicates:** not accepted as is, see m-5 (per-call account).
- **`DumpAllRowsAsync` 4-byte hex groups:** accepted. Ungrouped, a 32-byte HMAC has roughly a 1-3 % chance of containing 16 consecutive 0-9 hex digits. With the fixed dev key that becomes a permanent false positive for some seed numbers. The cost is that a PAN stored as ASCII bytes in a binary column would no longer be flagged. The only binary column is `LookupHash`, which T-I-16 pins to the HMAC. Keep the doc comment.
- **`SystemClock` / `SeededAdminActor` untested here:** accepted. This is trivial forwarding (writing-good-tests: no test unless it validates, derives or has side effects). The first consumer-visible results are PR-09's audit actor and PR-08's decided-at assertions.
- **Not strictly one-red-at-a-time:** a process deviation. The mutation table above backs the behaviour, except for the two gaps raised as m-3 and M-1/M-2.

## Spec / design coherence
- AC-21 (R-12): the lock is correct per DEC-4. Contract C-10 (`Serialises_work_on_the_same_card`) and T-I-17 cover serialisation, per-card scope and the 5 s bound. The end-to-end 5-of-10 check is T-I-6 in PR-08, as the brief says.
