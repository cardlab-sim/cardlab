## Judgement on the deviations the orchestrator asked about
- **`/^Submit/` instead of `/^Simulate/`**: correct. The simulate button's label is "Submit" (`web/src/pages/cardDetail/sections.tsx:393-394`, design §5 doc comment at `:306`). `/^Simulate/` in F-2 was my own error in the feature review. The pending label is "Simulating…", so the regex cannot match the pending state by mistake. The orchestrator's mutation shows the step is load-bearing.
- **`restartFromTop`** (`tests/e2e/src/a11y.spec.ts:42-48`): this is a legitimate scaffold for AC-37 as written. Each *action* is still started by Tab navigation plus Enter, and a real keyboard user can finish every journey (Shift+Tab gets back to Unfreeze in both engines, per my probe). But the helper's premise is wrong. It is not a Firefox quirk. In **both** engines the focused button is natively `disabled` while pending (`web/src/components/Button.tsx:31`), so focus falls to `<body>` after every Freeze, Unfreeze, Save, Remove and Submit. The old Chrome-only test passed only because Chromium wraps round within 50 presses. So the defect existed before this PR, and T-E-5 has never been able to see it. Fixing it is a design decision (M-1) and outside PR-13's ownership. For this PR, only the comments need to become truthful (m-1).
- **F-5 CI chain** (`ci.yml:129,147-148`): publish stamps `SourceRevisionId`, `CardLab__Commit` is gone from the start step, and the new step compares `jq -r .commit` with `github.sha` (the default `bash -e` shell fails on a curl error, because an empty string ≠ the SHA). My reading of the F-5 mutation (`ResolveCommit` returns the whole `x.y.z+sha`) is that it would fail this step. CI passing shows the stamping works today.
- **F-7**: the `local-firefox` project mirrors `local` (smoke excluded, same baseURL). CI installs `chromium firefox` and runs both projects. The config comment records Edge = shared Chromium engine, which matches the BUG-009 decision and design `:734`.
