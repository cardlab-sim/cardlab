# PR-11 review: Cross-path integration checks (limit changes, privacy, log events)

## Verdict: APPROVE WITH FIXES

0 blockers, 0 majors, 4 minors, 2 nits. The AC-30, AC-31 and AC-39 tests are precise. They use literal expectations
(`LimitRemainingDto("fuel","day","30.00","0.00")`, `"0001"`/`"0002"`, `"Sam Ellis"`, the exact Action sequence, and `"-"`
for unknown and invalid requests), exact counts and per-field checks. They are free of order dependence on the shared class
database: T-I-8a and T-I-8b use different cards (Ops van, Marketing), T-I-11a and T-I-11b use different cards (Ops van, Field
sales), each counting test calls `Logs.Clear()` first, and T-I-8b builds its own AC-30 state and first proves the lowered
limit is enforced. The `timestamp` values are fixed, which is safe: periods come from the request timestamp
(`AuthorisationService` remarks) and the validation window is 2000-2100 (`TransactionRules.cs:30-31`). The no-PAN scan
covers every response body, including ProblemDetails for malformed JSON. It also covers every base table through
`DumpAllRowsAsync` (via INFORMATION_SCHEMA), the four GET surfaces, and the message and attributes of every captured log
record. The minors are about vacuous guards in T-I-7 and one latent harness gap.
