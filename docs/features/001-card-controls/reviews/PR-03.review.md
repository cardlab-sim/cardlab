## Coder notes checked
- **`linuxFxVersion: 'DOTNETCORE|8.0'`**: a stack must be named, but 8.0 is the wrong one. See M-2.
- **App settings via `az webapp config appsettings set` instead of Bicep**: this matches the brief's PLANNER-DECISION and is sound. A `Microsoft.Web/sites` PUT that omits `siteConfig.appSettings` leaves existing settings untouched, and the CLI call merges. `azure-setup.md` step 8 has the post-second-deploy confirmation. The **position** of the step is wrong, though (B-1). The design text still says the settings come from Bicep (m-7).
- **SQL admin from repo variables with placeholder defaults**: fine. The defaults (`cardlab-demo`, `cardlab-demo-sql`, `sql-admin`, zero GUID) are obvious placeholders, not real identifiers. They exist only so CI's `build-params` succeeds, and the deploy job can never fall back to them (see Evidence).
